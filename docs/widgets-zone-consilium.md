# Панель: компактная галерея виджетов

## Короткая критика текущего состояния

**Дизайнер Windows 11 / WinUI:** «Сильная сторона — честный preview: тёмная пластина действительно похожа на виджет на панели. Отдельный `+`, счётчик и возможность перетаскивания дают понятные действия. Но карточки и межсекционные интервалы великоваты для каталога, а три варианта одного датчика выглядят как три разных сущности».

**Информационный дизайнер:** «Группировка хорошая, но структура повторяет данные вместо того, чтобы их сжимать. Больше всего высоты съедают 14 программ и тройки Load / Load + temperature / Temperature. При примерно 45 элементах каталог превращается в 3–4 экрана, хотя пользователь обычно ищет один объект».

**Скептический тестировщик:** «Новичок поймёт карточку: видит внешний вид, название и `+`. Он может не догадаться, что пластину можно перетащить, и не поймёт каталог, если подпись появится только по hover. Hover также не работает как надёжная подсказка для клавиатуры и тач-ввода».

## Согласованные принципы

1. Пластина-preview остаётся видимой до добавления; это главный мост между каталогом и реальной панелью.
2. Название не прячется только за hover. Hover может добавить детали, но не нести основной смысл.
3. У каждого видимого выбора есть явный `+`; drag-and-drop остаётся ускорителем, а не единственным способом.
4. Сжимать нужно повторы и навигацию: варианты одного датчика, длинный список программ, вертикальные заголовки.
5. Поиск работает по всему каталогу, даже если на экране показана одна категория.
6. Счётчик «на панели» остаётся рядом с добавлением и не конкурирует с названием.

## Четыре варианта и red-team

### A. Плотная галерея — 1740 px против ≈2680 px

Три колонки при ширине контента около 830 px, две — на минимальной ширине. Все категории, preview, подписи и `+` остаются на странице. Это самый безопасный эволюционный вариант: экономия около 35%, почти без переобучения. Минус — программы всё ещё создают длинный участок.

**Вердикт тестировщика:** проходит. Новичок видит всё, но скроллинг остаётся заметным.

### B. Левая навигация по категориям — фиксированные 820 px

Категории становятся rail; справа показывается одна категория, сверху глобальный поиск. Для 14 программ используется плотная сетка. На ширине меньше 620 px rail превращается в кнопку категории.

**Вердикт тестировщика:** проходит при двух условиях: первый экран открывает «Все виджеты» или «Рекомендуемые», а поиск явно обещает поиск по всем 45 элементам. Иначе новичок может принять активную категорию за весь каталог.

### C. Семейства устройств — 1110 px

CPU, Memory, GPU и другие устройства представлены одной карточкой. Сегмент Load / Load + temp / Temp обновляет preview; `+` добавляет текущий вариант. Программы свёрнуты в одну строку с количеством, системные элементы остаются сразу видимыми.

**Вердикт тестировщика:** лучший баланс. Названия вариантов видны до взаимодействия, preview остаётся честным, повторы исчезают. Риск — пользователь должен заметить, что `+` относится к выбранному сегменту; это нужно подтвердить микрокопией и сменой preview.

### D. Picker по кнопке Add widget — 760 px

На странице остаются уже добавленные виджеты и заметная кнопка `Add widget`. Она открывает компактный модальный каталог с поиском, фильтрами, preview и `+`.

**Вердикт тестировщика:** проходит как общий сценарий добавления, но это самое большое изменение модели. Кнопка должна быть в пустом состоянии и после первого добавления; закрытие не должно терять сделанные добавления.

## Что не прошло red-team

- **Подпись только по hover:** отклонено — скрывает основное значение, плохо для первого запуска, клавиатуры и touch.
- **Горизонтальные полки:** отклонены как основной паттерн — уменьшают высоту ценой невидимых элементов и добавляют второй тип прокрутки. Допустимы только для «Недавних» или «Рекомендуемых».
- **Сворачивать все редкие группы по умолчанию:** отклонено — создаёт ложное впечатление, что каталог короче за счёт скрытия, а не организации.

## Рекомендация

Строить вариант C и добавить к нему глобальный поиск из B. Он сохраняет любимый визуальный язык, сокращает каталог примерно на 59% и убирает именно содержательные повторы. Убрать hover-only подписи, горизонтальные полки и отдельные карточки трёх показаний одного устройства. Программы оставить одной явно раскрываемой строкой «Programs · 14».

Главные риски: неоднозначная связь сегмента с `+`, длинные локализованные названия сегментов и теснота на ширине 460 px. На узкой ширине семейная карточка должна переходить в две строки: preview сверху, сегмент и `+` снизу.
